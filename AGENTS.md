# AGENTS.md

Chrome MV3 extension ("Accessible AI Browser Navigator"): raw JS + CSS, no package.json, no build, no lint. A standalone Node benchmark lives in `bench/`. Verify in Chrome: `chrome://extensions` → Developer mode → **Load unpacked** → this directory. After editing, click Reload; content-script changes additionally require reloading the target page.

## Compliance workflow

- Code follows the Chrome "Modern Web Guidance" / chrome-extensions skill rules (MV3 only, async/await — no `.then()` chains, minimal permissions, error handling on all async ops). Keep it that way when editing.
- Permission justifications and privacy disclosures live in `README.md`. Update them whenever `manifest.json` permissions/host_permissions or data flow change.

## Architecture (message flow)

- `content.js` (injected on all pages): toggle overlay input via Ctrl+Shift+Y; collects visible interactive elements, stamps each with `data-a11y-id` (`p-0`, `p-1`, ...), sends `{action:"navigate_to_point", query, elements:[{id, r, t, zone, heading}]}` to background. Link collection keeps `mailto:` links (marked `email:true`) and names icon-only share links from `data-share` (email → "Condividi via email"), icon buttons from descendant `img[alt]`/`svg title`, and submit inputs from `value`; links dedupe by href+text after query ranking; one-shot focus activates mailto targets with a click instead of focus. Overlay offers Vai nella pagina (one-shot focus) and Naviga nel sito (multi-step browse). For browse it collects links as `{id (l-N), t, href, near, zone, heading}` — `zone` is the semantic region (`menu`/`testata`/`contenuto`/`laterale`/`piè di pagina` from `nav`/`header`/`main`/`aside`/`footer` landmarks) and `heading` is the nearest preceding heading in the link's section — with tracking params (`_gl`, `_ga`, `utm_*`, `fbclid`, …) stripped from every href and from the page URL, skips links that point to the current page (normalized so trailing-slash/query variants don't loop) and static-file links (pdf/zip/images/media), navigates to the Jev-chosen link's cleaned URL (falling back to an element click when no href is available), and auto-continues on every page load while a mission is stored; Esc/Interrompi stops it. It also appends JS-only menu toggles (`toggle:true`, no href — clicking reveals hidden nav links) and reports the site's own search field ids when present (`s-input`/`s-submit`), so Jev can choose `SEARCH_SITE` (the content types the original query, submits, then keeps browsing the results). Visible text prefers the main content container (`main`/`[role=main]`/`#content`/`article`/…) so Jev judges the page body, not the navigation chrome.
- `background.js` (service worker): relays the keyboard command as `{action:"open_input"}` to the active tab; on navigation it expands the query first into `{original, context, variants[]}` (on-device Prompt API — `LanguageModel`, legacy `aiLanguageModel` fallback, session destroyed after use — and, only when the browser yields nothing usable, via the OPTIONAL OpenAI-compatible refiner endpoint from the options config; both ask for a strict JSON contract with legacy single-keyword fallback), then ALWAYS delegates selection to **TypeSafe System One** (ONE `/v1/systemone` request batching three questions: a `choice` for the element, a `score` for match quality on a concrete 4-level rubric, and a `noul` gate for clear-match; choice `confidence`, resolved model and usage are logged). Quality below level 2 returns `{success:false, reason:"ambiguous", bestLabel, quality}` instead of navigating (content.js shows the best label as hint); missing quality, hallucinated id, absent key/config, or any network/API error degrade to substring match on `t`. On success replies `{success, targetId}`; content.js then scrollIntoView + focus `[data-a11y-id="<targetId>"]`. There is NO provider choice: Jev is the sole decision engine and the refiner only feeds it a better keyword (its call fails soft back to the previous intent). An empty Jev key skips the remote call with an Italian console warn (same UX as the former placeholder guard).
- `background.js` browse loop (`browse_start`/`browse_step`/`browse_stop`): keeps one mission `{original, expansion, jevApiKey, step, visited[], frontier[], trail[], stillCount, lastLinks}` in `chrome.storage.session` (never synced, cleared on stop/done/stuck/browser close; no step budget in research). Each step sends ONE `/v1/systemone` request (retried on 429/529/503) with structured state `{page:{url,title,text,dialogs,repeated_links,last_change}, goal, recent_actions[-10]}` (links travel only inside `click_target` criteria, never duplicated; candidates are re-ranked in code by `parole_essenziali`/original words over text+heading+near times a zone weight (menu > testata > contenuto > laterale > piè di pagina), and each link carries `near` row context, `zone` and `heading` so icon-only/generic links stay distinguishable) batching `operation` (CLICK/SCROLL_DOWN/SCROLL_UP/WAIT/DONE/BLOCKED plus SEARCH_SITE when the page has a search box, scroll options only when the page scrolls), `click_target` (choice over `l-N` links with text+URL, email links flagged, fail-closed validated: exact id set plus finite probabilities or no action executes), a `section` choice over the page's zones/section-headings (asked only when ≥2 exist; its answer boosts the matching links' frontier probabilities, so a link outside Jev's own chosen section can't win) plus `done`/`done_page` and `error` noul gates. Pages with more than 200 candidates get a two-stage flow: a pre-request picks the most promising zone/section, then only that section's links (plus a small fallback) are offered. Expansion also yields an `intento` (comprare/contattare/informarsi/…) and up to 4 `essenziali` (the specific terms that name the exact object sought, e.g. for "orari cinema" the show times, not the opening hours) that Jev must weight above generic terms; `mailto:` links are offered only when the user's ORIGINAL request itself is a contact one (the refiner's `intento` can never enable them, since a mislabel would otherwise open the email client), and the intent travels in `goal.intento` with a rule forbidding action shifts via synonyms. The mission pins the starting registrable domain (`mission.site`) and drops off-site links before every offer unless the query names another domain, so browse searches inside the site instead of drifting to linked vendors; the sterile-start web search clears the pin. Mailto picks return `done_email`: the content clicks the link (opens the mail client) and closes the mission via `browse_stop`, since no further page observes it. A sterile start page (BLOCKED, empty frontier, no local match at step 1) navigates once to a DuckDuckGo HTML search for the goal instead of dying. When the first 200 ranked options yield nothing actionable and more candidates exist, both flows page through the remaining 200-option chunks with the same question shape: one-shot takes the first pick passing the gates (else ambiguous/notfound from the best seen), browse takes the first passing link (else stuck). DONE switches to pinpoint focus on the reached page (content.js focuses the page's main heading and announces the title; it no longer re-runs element selection, which used to fail on informational pages) only after a stricter `complete` noul confirmation when the operation probability is below 0.85 (an unconfirmed DONE falls back to the backtrack path); independently, a high `done`/`done_page` reading from the page's main content triggers a `confirmBrowseTarget` noul and stops at the destination even when Jev would otherwise keep clicking (the page-content match is what makes "find this page" work on informational/service pages); a page `error` ≥ 0.7 ends as site_error; `last_change` (links added/removed, URL, text delta) is computed in content.js so Jev can judge progress; every CLICK spreads the full target probability mass into a beam `frontier[]` (top 20 by score, visited excluded, max kept per href) shown as alternative count, and BLOCKED or invalid answers backtrack to the best unvisited frontier entry instead of dying (target probabilities banked on every call, including BLOCKED ones; auto-scroll when scrollable and stalled) — a page with no usable links (static file, dead end) also backtracks to the frontier or scrolls rather than ending the mission; only an empty frontier ends the mission; 3 observations without progress end as blocked-stuck too. No `tabs`/`webNavigation` permission needed: continuation is content-initiated on page load.
- `options.html` / `options.css` / `options.js` (options page): store the TypeSafe Jev API key and, optionally, the refiner endpoint (base URL + key required, model optional with `GET /models` auto-detection falling back to `auto`) under the SAME storage key `llmProviderConfig` that `loadLlmConfig()` reads; per-service "Prova" buttons probe each endpoint plus a "Rileva modelli" button listing available ids. Custom hosts beyond the declared presets need the opt-in grant: the manifest lists `optional_host_permissions: ["https://*/*"]` and saving requests only the specific `https://<host>/*` pattern via `chrome.permissions.request()`. The page guards `chrome.storage.local` availability and shows an Italian error when opened outside the extension context. Keys live exclusively in storage.local — never log, commit, or pass them to content scripts.

## Gotchas

- **Element-id contract spans both scripts.** `data-a11y-id` is assigned in `content.js` and re-consumed there after the background round trip. Renaming the attribute or the message shape breaks navigation silently (status shows "Elemento non raggiungibile.").
- **No key material in the repo.** Both API keys (TypeSafe Jev + optional OpenAI-compatible endpoint) are entered in the options page and kept per profile in `chrome.storage.local` (key `llmProviderConfig`). Never hardcode keys back into `background.js` or commit real keys; testing means pasting the key into the loaded unpacked copy's options page. An absent/empty Jev key skips the remote call with an Italian console warn — deliberate, mirroring the old placeholder-guard UX.
- **Permissions stay host-scoped and opt-in.** No `permissions` entry at all (the on-device model API needs none per current Chrome docs; several builds warn on the unknown `aiLanguageModel` string; detection stays runtime `typeof`-guarded). Required grants are just `host_permissions` for api.typesafe.ai + api.openai.com; arbitrary custom endpoints rely on `optional_host_permissions: ["https://*/*"]` granted at save-time narrowed to the typed host. Do not widen to `<all_urls>` host_permissions or re-add `activeTab`/`scripting` without a concrete code path and verified browser support.
- **On-device model is optional.** `LanguageModel` (stable) / `aiLanguageModel` (older experimental builds) may be absent (Edge, older Chrome); the guards are deliberate graceful degradation — keep them. Empty model answers are ignored so they can't turn substring matching into a match-all.
- **Research build: no research caps, only API-contract caps.** Candidates are ranked by query-token overlap (full-phrase bonus) and sent whole with full texts; literal matches of the original words always outrank synonym matches (canonical example: email redazione → Redazione beats Scriveteci), synonyms only disambiguate paraphrases; a high-confidence pick (≥0.75 with quality ≥0.5) navigates even under the score gates; user query words outrank LLM synonyms everywhere: variants list query-first, Jev states carry `parole_originali` plus priority rule with tie-break instructions, local fallbacks match user terms before synonyms. the only cuts are `JEV_MAX_OPTIONS = 240` offered options (the API rejects more than 255 choices with HTTP 400) and full-body token fitting to ~24000 estimated tokens at 3 chars/token (the API fails past ~32k with `max_tokens_exceeded`), both keeping the best-ranked candidates — and neither is silent: when the offer was section-restricted (two-stage) or token-reduced, a failed step re-scans from the first chunk and the backtrack beam holds 30 alternatives, so a cap never permanently hides a candidate. Error bodies are surfaced in messages. Jev `choice` criteria always include a `zz-none` abstain option ("nessuna voce corrisponde") so the model never force-picks a wrong element. Watch token usage on huge pages.
- **Italian user-facing text.** All UI strings, ARIA labels, status messages, and LLM prompt text are Italian; new strings must match.
- **High-contrast styling is deliberate.** Black background / yellow border / bold white text in `styles.css` is an accessibility design choice, not a styling bug — do not "clean it up" without confirmation.

## Benchmark

- `bench/run.mjs` drives the real `background.js` (loaded with a mocked `chrome`) against **live sites**, with ground-truth URL checks and difficulty tiers 1→5 (`bench/tasks.mjs`): MDN, python.org, mozilla.org, gnu.org, Wikipedia, books.toscrape. Run: `node bench/run.mjs` (filters: `--tier N`, `--only id1,id2`). The Jev key comes from `TYPESAFE_API_KEY` or the macOS Keychain (`typesafe-api-key`). It fetches pages, mirrors content.js link/text extraction (zones, headings, tracking stripping, static-file skip), and follows the browse loop by fetching each chosen URL. Live sites change, so a failure may be the site; every line prints the URL actually reached.
- Current score: **12/12**. The relevance gate (below) closed the old not-found hole. If you change the browse gates, re-run the bench and keep R7/R8/R9 (off-site, mailto, tracking) green.

## Relevance gate (browse)

- Each browse step also asks a `relevance` Score (0–3) and an `on_topic` Noul alongside operation/click_target/done/error. Code decides: a `CLICK` is dropped when the page is off-topic (`relevance < 1` and `on_topic < 0.4`) or the target is unsure (`confidence < 0.55`); off-topic pages bank nothing into the frontier. Two escapes keep it from over-blocking: a confident target on a somewhat-related page (`relevance ≥ 0.5`, `confidence ≥ 0.7`) is still followed, and the local fallback ignores stopwords (`pickLocalLink` filters terms ≤ 3 chars / common Italian words). `OFF_TOPIC_STREAK_MAX = 3` ends the mission as `notfound` ("Nessuna pagina pertinente trovata") instead of wandering. Thresholds live at the top of `background.js` (`MIN_BROWSE_RELEVANCE`, `MIN_TARGET_CONFIDENCE`).
